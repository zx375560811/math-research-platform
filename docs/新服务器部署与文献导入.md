# Axiom 数学研究平台：新服务器部署与文献导入

更新日期：2026-10-10。适用系统：Alibaba Cloud Linux 3，使用 root 通过 SSH 部署。

仓库：https://github.com/zx375560811/math-research-platform

本文以 `/opt/math-platform` 为固定部署位置，先通过 SSH 隧道使用网站。公网域名、反向代理和 HTTPS 不在本次快速部署范围内。

## 1. 先选部署方式

| 方式 | 结果 | 执行章节 |
| --- | --- | --- |
| 全新部署 | 新建数据库、重新注册管理员，上传并导入教材 | 2–8 |
| 保留旧服务器数据迁移 | 保留用户、邀请码、文献、分类、教材关联、阅读进度、笔记和 API 设置 | 2–5，然后 10；不要先重新注册和重复导入 |

**GitHub 保存程序，不保存你的文献和数据库。** 克隆仓库不能恢复原有账号、文件或阅读记录。

当前技术组成：Java 17 / Spring Boot、SQLite 文件数据库、原生 HTML/CSS/JavaScript。本地前端资源随仓库提供，包括 Morphicons、PDF.js、DjVu 阅读支持和公式渲染资源。服务器部署不需要 Node.js，也不需要单独安装 MySQL、PostgreSQL 或 SQLite 服务。管理员脚本使用 Python 3 标准库；建议使用 Python 3.8 或更高版本，当前导入工具兼容旧 Python 3.6 的路径和数据库备份方法。

## 2. 准备服务器和磁盘

服务器需要能够访问 GitHub 和 Maven 依赖仓库。通过 SSH 隧道访问时，只需确保电脑可以连接服务器的 SSH 端口；应用保持监听 `127.0.0.1:8080`。

本次六个系列上传目录约 **19 GB**。导入会复制到正式文献库，因此上传副本和正式副本合计约 **38 GB**，还要给操作系统、构建缓存、数据库和备份留空间。新服务器使用至少 80 GB 磁盘可作为当前规模的容量起点；若保留多份完整备份，需要进一步增加容量。CPU 和内存要根据实际并发调整，仓库服务当前 Java 最大堆内存为 256 MB，这不等于整台服务器的总内存需求。

上传前执行：

```bash
df -h /opt
```

上传后、正式导入前，`backend/data/files` 所在文件系统仍需有足够空间容纳新增文件。当前 19 GB 源目录，建议至少剩余约 20 GB；实际要求由导入脚本根据文件与数据库大小计算。PDF/DJVU 本身已压缩，打包不会保证大幅减小容量。

## 3. 区分电脑终端和服务器终端

| 终端 | 提示符示例 | 执行内容 |
| --- | --- | --- |
| Windows PowerShell | `PS C:\...>` | SSH 登录、SCP 上传、建立隧道 |
| 服务器 Linux | `[root@服务器 ...]#` | dnf、git、systemctl、Python 导入脚本 |

下文 `新服务器公网IP` 必须替换为实际 IP。不要继续使用旧服务器 IP，除非确实要操作旧服务器。

在电脑 PowerShell 登录：

```powershell
ssh root@新服务器公网IP
```

密码输入时不会显示字符。看到 `[root@...]#` 后才执行 Linux 命令。

## 4. 一次完成基础部署

以下各条命令都在**新服务器 Linux 终端**执行。每个代码块都只有一行，方便复制；上一条成功后再执行下一条。

### 4.1 安装环境

```bash
dnf install -y git java-17-openjdk-devel curl python3 tar
```

```bash
java -version; javac -version; python3 --version
```

Java 和 javac 应使用 17 或项目支持的更高版本。若系统已有多个 Java 导致默认版本不正确，使用 `alternatives --config java` 和 `alternatives --config javac` 选择相应版本。

Alibaba Cloud Linux 3 使用 dnf，官方发行版资料列有 Java 17 软件包：[官方系统差异说明](https://www.alibabacloud.com/help/en/alinux/getting-started/differences-between-alibaba-cloud-linux-2-and-alibaba-cloud-linux-3)。命令同时依据仓库现有部署配置。

### 4.2 克隆和构建

仅在 `/opt/math-platform` 尚不存在时执行克隆；如果已经存在，先确认它是本项目的 Git 仓库，再使用第 9 节更新命令。

```bash
git clone https://github.com/zx375560811/math-research-platform.git /opt/math-platform && cd /opt/math-platform/backend && chmod +x mvnw && ./mvnw -B package
```

第一次构建会下载 Maven Wrapper 所需工具和依赖，可能持续数分钟。看到 `BUILD SUCCESS` 后继续。无需全局安装 Maven。

### 4.3 创建服务账号、目录和常驻服务

```bash
id math-platform >/dev/null 2>&1 || useradd --system --user-group --home-dir /opt/math-platform --no-create-home --shell /sbin/nologin math-platform
```

```bash
install -d -o math-platform -g math-platform -m 700 /opt/math-platform/backend/data /opt/math-platform/backend/data/files && install -d -m 755 /opt/math-platform/imports && install -m 644 /opt/math-platform/backend/deploy/math-platform.service /etc/systemd/system/math-platform.service && systemctl daemon-reload && systemctl enable --now math-platform
```

服务首次启动自动初始化数据库。常驻服务使用专用账号，写入位置限于 `backend/data`；源码和构建产物由 root 维护。

### 4.4 检查服务

```bash
systemctl status math-platform --no-pager -l; curl -fsS http://127.0.0.1:8080/api/health
```

启动通常需要几秒；若第一次 curl 尚未成功，稍后再执行一次。期望看到 `active (running)` 和：

```json
{"status":"ok","database":"ok"}
```

服务启动成功后，运行目录为：

```text
/opt/math-platform/
├─ frontend/                    页面、样式、图标和阅读器资源
├─ backend/
│  ├─ target/math-server.jar    Java 可执行包
│  ├─ admin/                   服务器管理与导入脚本
│  ├─ deploy/                  仓库中的 systemd 配置模板
│  └─ data/                    运行数据，必须单独备份
│     ├─ math.db               SQLite 数据库
│     ├─ ai-secret.key         AI 密钥加密文件，创建时间取决于 AI 初始化
│     ├─ files/                正式文献文件
│     └─ backups/              导入工具生成的备份
└─ imports/                    上传暂存目录，不是正式文献库
```

实际服务配置：`/etc/systemd/system/math-platform.service`。

## 5. 在电脑访问网站

另开一个**电脑 PowerShell 窗口**，执行下面一行并保持窗口开启：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:18080:127.0.0.1:8080 root@新服务器公网IP
```

隧道成功后没有输出、窗口看似停住，是正常状态。不要在这个窗口继续输入其他命令。

电脑浏览器打开：

| 页面 | 地址 |
| --- | --- |
| 登录、注册及应用入口 | http://127.0.0.1:18080/ |
| 文档库 | http://127.0.0.1:18080/#/library |
| 数学与应用数学 | http://127.0.0.1:18080/#/apps/mathematics |
| 系列书籍 | http://127.0.0.1:18080/#/series |
| 管理平台 | http://127.0.0.1:18080/admin |
| 系列管理 | http://127.0.0.1:18080/admin#series |
| 管理员默认 AI API | http://127.0.0.1:18080/admin#ai |

电脑的 `127.0.0.1` 指电脑自己；服务器上的 `127.0.0.1` 指服务器自己。必须通过隧道才能在电脑使用上述地址。这是 SSH 端口转发，不需要另外安装内网穿透软件。

## 6. 首次创建管理员

此节只适用于全新数据库。若迁移旧数据，先按第 10 节恢复，再使用原账号登录。

在**服务器**生成一次性邀请码：

```bash
cd /opt/math-platform/backend && runuser -u math-platform -- python3 admin/create_invitation.py --days 30
```

复制输出的邀请码，在电脑网页注册自己的账号。没有默认账号或默认密码；新账号先是普通用户。邀请码完整值只在生成时显示一次。

注册成功后，在服务器执行授权。将 `YOUR_USERNAME` 替换为刚注册的用户名：

```bash
cd /opt/math-platform/backend && runuser -u math-platform -- python3 admin/grant_admin.py YOUR_USERNAME
```

网页退出后重新登录，访问 `/admin`。用户没有注册时，授权脚本会提示账号不存在。

## 7. 上传六个系列书籍

当前电脑文件位置：`D:\BaiduNetdiskDownload`，其六个子目录名称如下。请保留名称及内部子目录，脚本以顶层目录识别系列：

```text
D:\BaiduNetdiskDownload\
├─ Graduate Studies in Mathematics(GSM)
├─ Graduate Texts in Mathematics(GTM)
├─ Lecture Notes in Mathematics
├─ London Mathematical Society Student Texts
├─ SMM
└─ UTM
```

### 7.1 在服务器创建暂存目录

```bash
install -d -m 755 /opt/math-platform/imports/series
```

### 7.2 在电脑 PowerShell 一次上传六个目录

先进入文件所在目录：

```powershell
Set-Location -LiteralPath 'D:\BaiduNetdiskDownload'
```

然后整行上传。将 IP 换成新服务器 IP：

```powershell
scp -r '.\Graduate Studies in Mathematics(GSM)' '.\Graduate Texts in Mathematics(GTM)' '.\Lecture Notes in Mathematics' '.\London Mathematical Society Student Texts' '.\SMM' '.\UTM' root@新服务器公网IP:/opt/math-platform/imports/series/
```

文件多时上传较久，等待命令返回 `PS ...>`。上传中断可重新执行；scp 不提供可靠的断点续传，重传可能重新复制已有文件。压缩包、EPUB 等文件不会由当前系列导入工具自动解包或入库。

**不要在服务器终端运行带 `D:\...` 或 `C:\...` 的 scp 命令。** 否则 Linux 会把盘符误认为远程主机，报 `Could not resolve hostname d/c`。

### 7.3 在服务器修复读取权限并检查容量

```bash
chown -R root:math-platform /opt/math-platform/imports/series && chmod -R u+rwX,g+rX,o-rwx /opt/math-platform/imports/series
```

```bash
du -sh /opt/math-platform/imports/series/*; df -h /opt/math-platform/backend/data
```

上传成功只代表文件放在服务器上，尚未进入数据库或网站。

## 8. 预览并正式导入六个系列

### 8.1 预览

在服务器执行：

```bash
cd /opt/math-platform/backend && runuser -u math-platform -- python3 admin/import_series.py /opt/math-platform/imports/series
```

预览会读取全部文件并计算 SHA-256，过程可能长时间没有输出。结束后给出数量、系列分布、格式和跳过文件数，且不写数据库。

2026-10-10 已上传目录的实际预览为：

| 系列 | 文件数 |
| --- | ---: |
| Graduate Studies in Mathematics（GSM） | 275 |
| Graduate Texts in Mathematics（GTM） | 278 |
| Lecture Notes in Mathematics | 526 |
| London Mathematical Society Student Texts | 98 |
| SMM | 234 |
| UTM | 180 |
| 合计 | 1591 |

其中 PDF 1540 个、DJVU 51 个、不同内容 1590 份，另跳过 2 个其他格式文件。此表是当时的目录快照；以后添加或删除文件，预览数量会变化。

### 8.2 正式追加导入：一行命令

确认剩余空间足够后执行：

```bash
cd /opt/math-platform/backend && systemctl stop math-platform && (runuser -u math-platform -- python3 admin/import_series.py /opt/math-platform/imports/series --apply; task_import_status=$?; systemctl start math-platform; exit "$task_import_status")
```

导入期间网站停止服务，结束后命令会尝试恢复服务；脚本报错后也会执行恢复服务。保持 SSH 连接，不要用 Ctrl+Z 挂起任务。若 SSH 意外断开或手动终止，重新登录后检查服务并启动；不要在导入进程仍运行时启动第二次导入。

工具行为：

- 先检查系列数据表、源文件和空间，并备份数据库及已有 AI 加密密钥。
- 复制 PDF/DJVU 到 `data/files`，保留目录结构，并自动关联到六个系列。
- 按内容去重，已存在的相同文件复用原文献 ID；同一本书可以关联多个系列。
- 不删除旧文献，不修改旧推荐教材、账号、阅读进度和笔记。
- 数据库事务失败时回滚，并清理本次新复制的文件。
- 重复执行不会重复入库；它是追加导入，不会随源目录删除而自动删除已入库的书。

初期扫描和校验仍可能没有输出；进入文件处理阶段后，每 100 个文件显示一次进度。成功结果包含 `new_documents`、`new_series_links`、`reused_files`、`backup`。系列导入生成的是数据库备份，不是整套文献文件备份；完整迁移仍使用第 10 节。

### 8.3 导入后验收

```bash
systemctl is-active math-platform; curl -fsS http://127.0.0.1:8080/api/health
```

网页 Ctrl+F5 刷新后，检查六个系列、内部目录、书籍搜索、PDF/DJVU 阅读及进度保存。同内容文件去重后，某个系列的书籍数量可能小于源目录文件数。

后台 `/admin#series` 可以调整系列信息、关联现有文献目录和移除关联。移除系列关联不删除原文献。此脚本已自动关联系列，无需再手动重复添加。

## 9. 日常更新与其他文献导入

### 9.1 更新代码：一行命令

```bash
cd /opt/math-platform && git pull --ff-only && cd backend && ./mvnw -B package && systemctl restart math-platform
```

Git 更新保留被忽略的运行数据；数据库迁移在启动时执行，所以重要更新前仍应备份。构建失败时不会执行重启。静态前端随 Git 更新，由 Java 服务提供；浏览器 Ctrl+F5 清除旧缓存。

### 9.2 普通单本 PDF/DJVU

少量文献可在管理平台上传；应用没有固定 20 MB 上传上限，仍受磁盘、连接、服务或后续代理配置影响。

服务器已上传的单本文件，可通过下列命令导入。路径、标题、作者按实际修改：

```bash
cd /opt/math-platform/backend && runuser -u math-platform -- python3 admin/import_document.py /opt/math-platform/imports/paper.pdf --title '真实书名' --authors '作者' --subject-id 3
```

`subject-id`：1 代数、2 数论、3 分析、4 几何与拓扑、5 其他。源文件必须对服务账号可读，脚本不会自动将单本文献关联系列；可在后台关联。

### 9.3 Zotero RDF 批量导入

从 Zotero 导出 RDF 时包含文件附件，保持 `.rdf` 与 `files/` 等附件目录的相对结构。上传整个导出文件夹后预览：

```bash
cd /opt/math-platform/backend && runuser -u math-platform -- python3 admin/import_zotero.py '/opt/math-platform/imports/大学数学基础/大学数学基础.rdf'
```

确认报告后导入：

```bash
cd /opt/math-platform/backend && runuser -u math-platform -- python3 admin/import_zotero.py '/opt/math-platform/imports/大学数学基础/大学数学基础.rdf' --apply
```

这同样是追加导入，保留 Zotero 目录关联；真实路径按实际导出目录修改。完整说明见 `backend/README.md`。

### 9.4 普通课程文件夹与全量替换的区别

`admin/replace_library.py` 是之前为“数学文献”课程目录开发的**全量替换工具**，并且要求受支持的课程顶层目录。它不是任意目录的追加导入器，也不适用于六个系列目录。

本次使用 `import_series.py`，不要改用 `replace_library.py --apply --replace`，否则会替换旧文献与推荐配置。任意新目录如需批量追加，需要按对应导入工具的输入格式整理，或另行扩展工具。

### 9.5 AI 设置

管理员在 `/admin#ai` 配置默认 OpenAI 兼容 API 地址、模型和密钥并启用；用户可保存自己的 API。API 地址应为兼容接口基地址，不是控制台密钥管理网页。系列推荐依据库中已有书籍元数据，不自动读取整本书；推荐结果进入同一个阅读器。

## 10. 完整备份与迁移已有数据

### 10.1 在旧服务器生成一致性备份

停服期间备份 `backend/data`，包含数据库、正式文献文件、阅读记录和 AI 加密密钥。以下命令排除 `data/backups` 下的历史备份，避免反复打包；现用数据仍会完整包含。备份目标要有足够空间。

在**旧服务器**执行：

```bash
install -d -m 700 /opt/math-platform-backups && systemctl stop math-platform && (task_backup_file="/opt/math-platform-backups/math-data-$(date +%Y%m%d-%H%M%S).tar.gz"; tar --exclude='data/backups' -C /opt/math-platform/backend -czf "$task_backup_file" data; task_backup_status=$?; systemctl start math-platform; if [ "$task_backup_status" -eq 0 ]; then printf '%s\n' "$task_backup_file"; fi; exit "$task_backup_status")
```

保留输出的实际备份文件名。备份包含账号与 API 配置，按私人数据保管，不上传 GitHub。

**本次六个系列尚未入库，`imports/series` 的 19 GB 不包含在 data 备份中。** 新服务器仍需从电脑上传并导入六个系列；已入库文献则从备份恢复，不必重复导入。

### 10.2 通过电脑传输备份

在**电脑 PowerShell**执行，替换旧、新 IP 和实际文件名：

```powershell
scp root@旧服务器公网IP:/opt/math-platform-backups/math-data-实际时间.tar.gz .
```

```powershell
scp '.\math-data-实际时间.tar.gz' root@新服务器公网IP:/opt/math-platform-backups/
```

上传前在**新服务器**创建目标目录：

```bash
install -d -m 700 /opt/math-platform-backups
```

### 10.3 在新服务器恢复

先完成第 2–5 节代码部署，确认可以运行，然后停止服务。恢复用于**新服务器且尚未注册、未导入新内容**的场景，避免混合两套数据库。先检查备份包：

```bash
tar -tzf /opt/math-platform-backups/math-data-实际时间.tar.gz | head -20
```

内容应以 `data/` 开头，来自上面的可信备份。正式恢复前，将新建 data 目录整体留作回退，再解压，避免遗留新建数据库的 WAL/SHM 文件混入旧备份：

```bash
systemctl stop math-platform && mv /opt/math-platform/backend/data "/opt/math-platform/backend/data-before-restore-$(date +%Y%m%d-%H%M%S)" && tar -xzf /opt/math-platform-backups/math-data-实际时间.tar.gz -C /opt/math-platform/backend && chown -R math-platform:math-platform /opt/math-platform/backend/data && systemctl start math-platform
```

如果恢复任一步报错，先处理错误再启动，不要让服务在缺失或半恢复的数据目录下运行。确认服务后用原账号重新登录；登录会话不跨服务器保存，但数据库中的账号、文献和笔记保留。不要遗漏 `ai-secret.key`，否则已有 API 密钥可能无法解密。

## 11. 常见故障速查

| 现象 | 原因与处理 |
| --- | --- |
| 电脑浏览器 `127.0.0.1` 拒绝连接 | 隧道未建立或已关闭；重新执行第 5 节，保持窗口开启 |
| 隧道提示本地 18080 已占用 | 换本地端口，如 `18081:127.0.0.1:8080`，浏览器也改为 18081 |
| 服务器服务不断重启 | 查看日志；不要另开 `java -jar` 与 systemd 同时运行 |
| `Cannot start` 或端口占用 | `ss -ltnp 'sport = :8080'` 确认进程；识别后结束旧手动进程，再启动服务 |
| `Permission denied` | 暂存目录缺少读取/进入权限；执行第 7.3 节；入库脚本工作目录必须是 backend |
| `Could not resolve hostname c/d` | Windows 本地文件路径被放到 Linux 终端；回电脑 PowerShell 上传 |
| Windows `sudo -u`、`head`、`ls -ld` 报错 | Linux 命令在 PowerShell 执行；先 SSH 登录 |
| `PY: command not found` | 误粘贴了脚本结束标记；本文命令不需要输入 PY |
| 导入暂时没有输出 | 预览/导入正在扫描并计算 SHA-256；大量文件需等待 |
| `Not enough disk space` | 上传暂存与正式库同时占空间；检查 `df -h`，容量不足则扩容或使用更大新服务器 |
| 缺少系列表或系列名称不匹配 | 先部署并启动当前 Java 后端；确认后台六个系列未被改名或删除 |
| 旧脚本缺少 `is_relative_to` 或 `Connection.backup` | 先 git pull 更新当前脚本；不要继续使用旧版本副本 |
| 页面内容还是旧样式 | 确认 Git 更新及服务重启成功，再 Ctrl+F5 |
| DjVu/PDF 不能选中文字 | 可能是无文字层扫描文件；格式支持不等于自动 OCR |
