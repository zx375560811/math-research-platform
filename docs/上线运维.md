# 公网上线与日常运维

本文档补齐“从 SSH 隧道访问”到“公网域名 + HTTPS”的上线步骤，以及备份、监控、发布回滚和故障排查。应用本身仍只监听 `127.0.0.1:8080`，公网流量必须经过本机反向代理。

仓库中的相关文件：

| 文件 | 用途 |
| --- | --- |
| `backend/deploy/Caddyfile.example` | Caddy 2 反向代理 + 自动 HTTPS（推荐） |
| `backend/deploy/nginx.conf.example` | Nginx + certbot 方案 |
| `backend/deploy/release.sh` | 构建、备份、重启、健康检查、失败回滚 |
| `backend/deploy/math-platform.service` | systemd 常驻配置 |
| `backend/admin/backup_database.py` | SQLite 在线热备份与轮换 |

---

## 1. 上线前检查

在服务器执行：

```bash
systemctl is-active math-platform
curl -fsS http://127.0.0.1:8080/api/health
df -h /opt
ss -ltnp 'sport = :8080'
```

确认：

- `/api/health` 返回 `{"database":"ok","status":"ok"}`；
- 8080 只监听 `127.0.0.1`；
- `/opt` 剩余空间至少能容纳一份完整 `data/` 备份；
- 已把数据库、`data/files` 和 `ai-secret.key` 备份到服务器之外。

域名准备：为 `math.example.com` 添加 A 记录指向服务器公网 IP；云安全组放行 TCP 80、443（22 仅对管理 IP 开放）。**不要**对公网放行 8080。

## 2. 反向代理与 HTTPS

### 2.1 Caddy（推荐，自动证书）

安装 Caddy 2（以官方仓库为准，Alibaba Cloud Linux 3 可用 COPR）：

```bash
dnf install -y 'dnf-command(copr)'
dnf copr enable -y @caddy/caddy
dnf install -y caddy
```

把 `backend/deploy/Caddyfile.example` 复制为 `/etc/caddy/Caddyfile`，替换域名与邮箱后校验并重载：

```bash
caddy validate --config /etc/caddy/Caddyfile
systemctl enable --now caddy
systemctl reload caddy
```

Caddy 会自动申请并续期证书。确认 80/443 已放行，且没有其他服务占用。

### 2.2 Nginx（可选）

```bash
dnf install -y nginx certbot python3-certbot-nginx
certbot --nginx -d math.example.com
```

把 `backend/deploy/nginx.conf.example` 复制为 `/etc/nginx/conf.d/math-platform.conf`，按实际证书路径修改，然后：

```bash
nginx -t && systemctl reload nginx
```

示例已关闭 `proxy_buffering`（AI SSE 流式回答需要）、关闭请求缓冲并把上传大小设为 0（文献上传不设应用层上限）。

### 2.3 应用侧：信任代理头

反向代理会追加 `X-Forwarded-For`。仓库的 systemd 配置已加入：

```ini
Environment=MATH_FORWARD_HEADERS=native
```

它让登录/注册限流按真实客户端地址计数。修改单元文件后：

```bash
systemctl daemon-reload && systemctl restart math-platform
```

应用只监听回环地址，因此信任本机代理头是安全的；如果直接从隧道访问、没有代理，不要手动伪造这些头。

### 2.4 HTTPS 下启用 Secure Cookie

应用默认不为会话 Cookie 设置 `Secure`，以便继续通过 SSH 隧道（HTTP）使用。**确认 HTTPS 正常后**，在 `math-platform.service` 的 `[Service]` 中追加：

```ini
Environment=MATH_COOKIE_SECURE=true
```

然后 `systemctl daemon-reload && systemctl restart math-platform`。浏览器 DevTools 中 `JSESSIONID` 应带 `Secure; HttpOnly; SameSite=Lax`。若仍需用 HTTP 隧道调试，先去除此行。

## 3. 防火墙与端口

```bash
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
firewall-cmd --list-all
```

最终对外只保留 22、80、443。确认：

```bash
ss -ltnp
```

应看到 80/443 由 Caddy/Nginx 监听，8080 仅 `127.0.0.1`。

## 4. 上线验收

```bash
curl -fsS https://math.example.com/api/health
curl -sI https://math.example.com/ | grep -iE 'strict-transport|content-security'
curl -s -o /dev/null -w '%{http_code}\n' https://math.example.com/api/subjects   # 期望 401
```

浏览器检查：

1. 访问 `https://math.example.com/`，确认证书有效、HTTP 自动跳转 HTTPS。
2. 使用邀请码注册并登录；DevTools 确认 `JSESSIONID` 带 `Secure`。
3. 打开一本大 PDF，翻页、缩放正常；Network 中 `/file` 请求出现 `206 Partial Content`。
4. 上传一份大于 20 MB 的 PDF，确认没有被代理拦截（Nginx 应为 `client_max_body_size 0`）。
5. 在阅读器发一次 AI 提问，确认回答逐字流式出现，而不是等整段返回。
6. 手机访问，确认导航与阅读器布局正常。
7. 退出登录后直接访问 `/api/documents`，应返回 401；普通账号访问 `/admin` 应被拒绝。

## 5. 备份与恢复演练

### 5.1 每日备份

仓库自带 systemd 定时器模板：

```bash
install -m 644 backend/deploy/math-platform-backup.service /etc/systemd/system/
install -m 644 backend/deploy/math-platform-backup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now math-platform-backup.timer
systemctl list-timers math-platform-backup.timer
```

备份文件位于 `backend/data/backups/`，包含数据库和 `ai-secret.key`，默认保留 14 份。**备份目录与数据库在同一块磁盘，不构成灾难备份。**

### 5.2 异地备份

任选其一，把 `backend/data/backups/` 同步到对象存储或另一台机器：

```bash
# rclone（推荐，支持 S3/OSS/WebDAV 等）
rclone sync /opt/math-platform/backend/data/backups remote:math-platform-backups --min-age 1h
```

```bash
# rsync（目标机需 SSH 免密）
rsync -a --delete /opt/math-platform/backend/data/backups/ backup@backup-host:/srv/math-platform/backups/
```

配置为独立 timer 或 cron，并监控“最近一次成功备份时间”。备份包含账号哈希与 AI 密钥，上传前应加密（如 `age`、`gpg`），且不要放入 Git。

### 5.3 恢复演练（每季度至少一次）

在维护窗口、停服状态下进行：

```bash
systemctl stop math-platform
cp -a /opt/math-platform/backend/data /opt/math-platform/backend/data-before-restore-$(date +%Y%m%d-%H%M%S)
cp /opt/math-platform/backend/data/backups/math-YYYYMMDD-HHMMSSZ.db /opt/math-platform/backend/data/math.db
cp /opt/math-platform/backend/data/backups/math-YYYYMMDD-HHMMSSZ.ai-secret.key /opt/math-platform/backend/data/ai-secret.key
rm -f /opt/math-platform/backend/data/math.db-wal /opt/math-platform/backend/data/math.db-shm
chown -R math-platform:math-platform /opt/math-platform/backend/data
systemctl start math-platform
curl -fsS http://127.0.0.1:8080/api/health
```

恢复后验证：

- `python3 -c "import sqlite3;print(sqlite3.connect('data/math.db').execute('PRAGMA integrity_check').fetchone()[0])"` 输出 `ok`；
- 能登录、打开 PDF、看到历史高亮；
- AI 默认密钥仍可解密（说明 `ai-secret.key` 与数据库配套）；
- 记录演练日期与耗时。没有演练过的备份不能视为可用。

## 6. 监控与日志

最低限度：

- 外部 uptime 监控 `https://math.example.com/api/health`，期望 200 且响应包含 `"status":"ok"`；连续 2 次失败告警。
- 磁盘使用率告警（`/opt` 超过 80%），文献库增长主要来自 PDF/DJVU。
- 备份任务最后成功时间告警。
- TLS 证书到期告警（Caddy 自动续期，但仍需监控）。

日志：

```bash
journalctl -u math-platform -n 100 --no-pager -l
journalctl --disk-usage
```

需要限制日志占用时，在 `/etc/systemd/journald.conf` 设置 `SystemMaxUse=`，然后 `systemctl restart systemd-journald`。

## 7. 发布与回滚

### 7.1 一键发布

```bash
sudo /opt/math-platform/backend/deploy/release.sh
```

脚本按顺序执行：`git pull --ff-only` → 备份数据库与 AI 密钥 → 保存当前 JAR 快照 → 停止服务 → Maven 构建 → 启动服务 → 60 次健康检查（约 2 分钟）。构建失败会自动恢复上一版 JAR 并启动；健康检查失败会回滚上一版 JAR。

发布期间服务会暂停；依赖已缓存时通常 1–2 分钟，首次构建可能更久。**不要在服务运行时直接替换 `target/math-server.jar`**：运行中的 JVM 会惰性读取嵌套 JAR，替换后可能出现 `ClassNotFoundException`（线上曾出现 logback `ThrowableProxy` 错误）。

JAR 快照保存在 `backend/data/releases/`，默认保留 5 个。

### 7.2 手动发布

```bash
cd /opt/math-platform && git pull --ff-only
cd backend
runuser -u math-platform -- python3 admin/backup_database.py --database data/math.db --output-dir data/backups --keep 14
systemctl stop math-platform
./mvnw -B package
systemctl start math-platform
curl -fsS http://127.0.0.1:8080/api/health
```

先备份、再停服、后构建。**不要在服务运行时执行 `./mvnw package`**：替换 `target/math-server.jar` 会让运行中的 JVM 在后续惰性加载类时失败。构建失败时旧 JAR 仍在 `target/`（发布脚本还会保留快照），先启动旧版本再排查。

### 7.3 回滚边界

- 只回滚 JAR 可以恢复代码行为，但数据库迁移是前向的：新版本已执行的建表/加列不会自动撤销。
- 若新版本写入了不兼容数据，必须停服后用发布前的 `data/backups` 恢复数据库。
- 静态前端随 Git 更新由服务直接读取，回滚 JAR 不会回滚 `frontend/`；必要时对前端文件单独 `git checkout` 旧版本。
- 重启会清空内存会话，所有用户需要重新登录（最长 12 小时会话，见 README）。

## 8. 安全检查清单

- SSH 仅密钥登录，禁用 root 密码登录；22 端口限制来源 IP。
- 云安全组只开放 22/80/443；8080 不对公网开放。
- 系统与依赖定期更新；关注 Spring Boot / SQLite JDBC 安全公告。
- 管理员账号保持最少数量；离职或换人后立即 `grant_admin.py --revoke`。
- 邀请码按人发放、设置有效期；发现泄露立即撤销。
- `ai-secret.key` 与数据库一起备份，权限 0600，不进入 Git。
- HTTPS 启用后设置 `MATH_COOKIE_SECURE=true` 与 HSTS（示例配置已含 HSTS）。
- 反向代理只转发到 `127.0.0.1:8080`，不要额外暴露管理路径。
- 定期检查 `journalctl` 中的登录失败、429、500 与 AI 上游错误。

## 9. 常见故障

| 现象 | 排查 |
| --- | --- |
| 502 Bad Gateway | 应用未启动：`systemctl status math-platform`、`curl 127.0.0.1:8080/api/health` |
| 登录后立即掉线 | 启用 `MATH_COOKIE_SECURE=true` 但仍在用 HTTP 访问；改回 HTTPS 或临时去掉该变量 |
| 所有用户共享限流 | 未设置 `MATH_FORWARD_HEADERS=native`，或代理未传 `X-Forwarded-For` |
| AI 回答不流式 | 代理开启了缓冲：Caddy `flush_interval -1`，Nginx `proxy_buffering off` |
| 上传大 PDF 返回 413 | Nginx `client_max_body_size` 太小；示例中为 0 |
| 上传中途超时 | 代理 `proxy_read_timeout` / `proxy_send_timeout` 过短；示例为 300s |
| 证书未续期 | `systemctl status caddy` 或 `certbot renew --dry-run`；检查 80 端口 |
| 备份文件很大 | 备份含整个 SQLite；文献 PDF 不在数据库中，需单独备份 `data/files` |

完整数据备份（含 PDF/DJVU）与迁移步骤见 [新服务器部署与文献导入](新服务器部署与文献导入.md) 第 10 节。
